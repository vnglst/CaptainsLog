# Testing Plan: End-to-End Coverage Without Xcode

**Status:** Deterministic plan is implemented; 184 full-suite checks and 132 lightweight unit checks pass. Hardware capture and the standalone installed-model smoke remain opt-in integration gates. Remaining OS-owned/native gaps are listed below.  
**Baseline reviewed:** 2026-09-26

## Goal

Cover every user-visible app workflow through a combination of deterministic command-line tests, full CLI workflows, stage evaluations with human semantic review, and targeted native UI checks. Builds and deterministic tests must use Swift Package Manager and Apple Command Line Tools; no Xcode IDE, XCTest, or Swift Testing dependency is allowed. Model and recording checks remain opt-in because they need downloaded models or real hardware.

The test runtime must be isolated. Set `CAPTAINS_LOG_CONFIG_PATH` to a temporary config before launching the CLI or app, set its `dataDir` to a temporary directory, and seed that directory only from repository fixtures under `eval/`. Never use `processed/`, Obsidian, a user's CaptainsLog directories, or the default `DemoMode` data (which copies `demo/`) as a test source. `DesignFixtures.swift` contains hard-coded presentation examples; do not count those as repository test fixtures under the privacy rule. The native harness composes existing stage fixtures from `eval/` into a temporary data directory, then uses state injection only to select presentation state.

## Existing foundation and gaps

`swift run run-tests` executes a framework-free test executable in `Sources/run-tests/main.swift`. GitHub Actions uses `swift run run-tests --unit`, which omits the separate workflow, search-index, coordinator, and pipeline-orchestration groups; running without `--unit` executes the full suite. Unit tests include config persistence/migration, malformed-config recovery, directory precedence, prompt construction, filename normalization, local GGUF selection, categorization parsing, pipeline stage selection/recovery, search manager transitions, Markdown parsing, the pure UI policy/state for onboarding, entry navigation, row actions, the recording dock and queue strip, plus recorder lifecycle through injected fake engine/writer operations (device selection/fallback, tap install, RMS levels, pause gating, write/start failures and release). They also cover model readiness/download progress, directory watcher lifecycle, and AppState transitions. Workflow tests cover Logs loading/deletion, resume/queue/pause/retry, row errors, missing-audio safety, onboarding persistence, fresh audio-copy runs, audio-import safety, each pipeline resume stage, settings reload, folder-picker outcomes, and context reload. Search tests cover empty queries, frontmatter indexing, ranking, manager cancellation/invalidation/reuse/retry. CLI fake-operation checks cover transcribe, cleanup, enrich, filename and categorize success/failure; pipeline tests cover fresh runs, stage failures, missing audio and all resume paths. Latest full-suite run: **184/184 passed**; latest lightweight suite: **132/132 passed**. `scripts/test-coverage.sh` checks command help, validation, temp-config persistence, six `cl list` stages and prompt rendering. Latest coverage: **31.58%** all-source line coverage (37.86% functions; 41.82% regions) and **82.16%** deterministic-production line coverage, 2.16 percentage points above the enforced 80% floor. Scope and exclusions are documented in ADR-007.

Most workflow tests assert user-visible state plus resulting files: CLI fake operations exercise stage outputs and failures, AppState exposes row-level errors and retries, and pipeline resume tests inspect preserved or regenerated artifacts. Remaining gaps include the raw AVFoundation adapter boundary, some OS-owned panel outcomes, and further extraction of UI decisions where it creates a useful deterministic seam. `scripts/test-recorder-hardware.sh` and `scripts/test-model-smoke.sh` define opt-in gates; neither was run as part of this deterministic verification. Inference quality remains a separate human-reviewed eval gate; the current transcription report records a quality failure rather than a pass.

## Evaluation suite and review

Keep stage-specific evaluation instructions in `skills/<stage>-eval/SKILL.md` as the source of command details. Run one inference task at a time, sequentially, because WhisperKit and llama.cpp share on-device GPU memory. Reuse one loaded Qwen model within each pipeline run. For every run, save generated output and a report beneath the suite's ignored `generated/` and `reports/` directories. This pass generated and semantically reviewed transcription, cleanup, filename and enrichment results; the semantic summary is [`TESTING-EVAL-REPORT.md`](./TESTING-EVAL-REPORT.md). Transcription failed quality review because proper names/topic phrases were changed or omitted. Pipeline artifact assertions and search readback passed; they do not override the semantic quality failure.

1. Transcription: the sequential run reviewed all four synthetic audio fixtures under `eval/transcribe/audio/` against `eval/transcribe/expected/`. Reports found dropped/changed proper names and phrases, a topic-changing “science project” recognition, and an added `[BLANK_AUDIO]` marker. Quality gate: failed; see `TESTING-EVAL-REPORT.md`.
2. Cleanup: all three inputs were reviewed against `eval/cleanup/expected/`; see `TESTING-EVAL-REPORT.md` for preserved facts and omissions.
3. Categorization: `eval/categorize/` has four synthetic cases covering all three labels and a mixed memo; `bash scripts/run-evals.sh --categorize` runs them sequentially and validates JSON structure, source stem, and expected label. Human semantic review is recorded in `TESTING-EVAL-REPORT.md`.
4. Filename: all eight cases were generated and structurally checked; semantic changes including lost contrast/context are documented in `TESTING-EVAL-REPORT.md`.
5. Enrichment: all four cases were reviewed; saved outputs passed YAML/frontmatter validation after a sequential rerun of one initially empty artifact. See `TESTING-EVAL-REPORT.md`.
6. Search: use every query in `eval/search/queries.json` against a clean index of the synthetic notes in `eval/search/`; `eval/search/README.md` documents these fixtures. Review ranking, expected hit visibility, false positives, and useful excerpts.
7. End-to-end pipeline: the `2025-01-14 side project` synthetic audio fixture completed every stage in isolated temp data; resume was idempotent and search readback found the final entry. Semantic issues and a variable derived recording time are documented in `TESTING-EVAL-REPORT.md`.

Do not make model evaluations parallel. Reports need examples of semantic changes and must record model, prompt/config, fixture, command, and date so results are reproducible. Human review remains the final quality judgment.
